---
id: phase-criteria
description: When a request gets a phase plan and when it does not
kind: convention
---
- Create a phase plan for EVERY new feature request, regardless of perceived size — a feature that seems small often grows during implementation. Use a single phase (1 of 1) if the scope is genuinely small.
- Do NOT create a phase plan only when: the request is a refactor, rename, or code cleanup; the request is a bug fix (even a complex one); the request is documentation-only; or the user explicitly says "do it all in one go".
